Home priority hierarchy — three directions

Owner brief, 2026-07-28: “this section is still confusing. it doesnt stand out what my priorities are.” Target is Home’s consequence stream (section.home-stream) for the owner-director persona. Content is the real seeded data at v4-redesign @ 1e459b0; tokens are the app’s own computed values. All three preserve the identity: cream surface, DM Sans body over a Plus Jakarta display face, flat full-width rows, no cards, no shadows.

Current — the diagnosis

Three failures compound. Severity is the last thing you reach: “Urgent”, “Needs attention” and “Overdue · 12d” sit at the right edge of a ~1090px row, so every judgement needs a full-width eye sweep. The bands group by record source (Signals / Overdue / Failed checks), which is a storage taxonomy rather than a priority one. An Urgent Signal and a 12-day-overdue Blocked task get filed apart and weighted the same. And every row carries the same weight, so nothing answers “what first”.

Six attention items and three routine ones also render at near-identical weight, so the boundary between must-act and can-wait is invisible.

A · Hierarchy — one thing commands the eye

The single most consequential item is promoted: display face, size step, a tinted panel. Band labels shrink, meta lines dim, and routine work drops to 76% opacity. The page now has one obvious entry point instead of nine equal ones.

Cost: it asserts a ranking the app must actually be able to compute. If “most consequential” is really just “first in the array”, this direction lies confidently, which is worse than the current flatness. Ship only with a real ranking behind it.

B · Topology — severity leads the line

The reason moves from the right tail to the front of the row, in a fixed 84px column, and rows regroup by urgency rather than by source. Severity becomes a single left-aligned column you read straight down; the record’s origin drops to the meta line where it belongs. No eye sweep, no colour-coded bars.

Cost: it needs one severity scale spanning Signals, tasks and failed checks. That is a product decision, not a CSS one. It also spends 84px of measure at desktop, and on phone the mark has to sit above the title.

C · Density — a two-column consequence table

Each band becomes label-left / items-right, so the kinds of problem are a scannable column and the rows tighten under them. Band labels move to the display face in sentence case, retiring the uppercase eyebrow. Routine work sits at 60%.

Cost: the most conservative of the three. It improves scanning without claiming a priority order, so it does the least about “what first”. It also degrades to the current stacked layout on phone, meaning the floor persona sees no benefit.
