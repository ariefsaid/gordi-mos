The one variable

Everything is held identical to spine A — same chrome, same data, same IA, same fonts, same status colors. The single added variable is lane color as a categorical signal: a .lane-tag (dot + label) and a .lane-dot, woven into objective rows, two KPI labels, and a dedicated table column. If a reviewer's eye is drawn to anything other than lane hue, the probe failed to isolate the variable.

The question

DESIGN.md's One-Blue Rule reserves the only saturated color for primary interactive blue. But a director scanning a dense task table is really asking one triage question — "is my team mostly keeping the lights on (Run), or moving forward (Optimize / Transform)?" Today that answer is invisible without reading every row. Does adding lane hue help that scan, or does it read as noise? The Work legend answers it in one line: 61% Run, 26% Optimize, 13% Transform — mostly keeping the lights on, with a healthy improve chunk. That sentence did not exist in variant A.

The argument — categorical color ≠ interactive color

The One-Blue Rule is a rule about interactive saturation: only blue looks clickable. Lane color is categorical — it is never clickable, never a button, never a link. It is the same kind of mark as the existing Tinted-Status Rule, which already permits four hues (blue / green / red / amber) plus a violet for KPI/timeline. This probe argues lane color is simply a second categorical axis (Run / Optimize / Transform) riding the same convention — an extension of the Tinted-Status Rule, not a violation of the One-Blue Rule. The two rules govern different channels: One-Blue governs "what can I click"; Tinted-Status governs "how do I read state at a glance." Lanes belong to the second.

Concretely: nothing in these screens stopped being blue when it should stay blue. The primary button, the selected-row wash, the focused input, the capture FAB, the "Open" pill — all still blue. Lane hue only appears on non-interactive dots, labels, and bar fills.

The fix applied here — Transform was colliding with brand-orange

Building this surfaced a real hue collision. base.css shipped --lane-transform: hsl(18 75% 48%) sitting on top of --brand-orange: hsl(18 80% 48%) — Δ hue 0°, Δ sat 5%. The active-tab underline and the active-rail stripe are brand-orange, so a Transform dot/bar read as "this thing is selected/active," not "this is a change lane."

--brand-orange hsl(18 80% 48%) --lane-transform hsl(8 78% 50%) — now → pushed redder + more saturated; no longer reads as the orange "active" accent.

This prototype applies the fix: --lane-transform is redefined to hsl(8 78% 50%) (redder), so it cannot be confused with brand-orange. Run (teal, hsl 200) is clean — no collision in the palette. Optimize (violet, hsl 262) reuses the existing categorical violet concept.

The cardinal risk — cap at 3 (hard), 4 (absolute)

The system works because a director can hold three lanes in working memory alongside the four status hues. That is already seven categorical colors on screen. A fourth lane is the ceiling; a fifth breaks the scan job the probe was built to serve and collapses back into "read every row." If the business ever argues for a fifth lane (e.g. "Compliance", "Innovation"), the answer is not a fifth color — it is to fold it into Run or Transform, or represent it as a tag, not a hue. Lanes are a fixed vocabulary of three; everything else is text.

What we deliberately did NOT lane (restraint is the finding)

Not every element got a lane dot. We left Revenue and Net cash KPIs un-laned: forcing a Run/Transform dot onto "Revenue MTD" created a false, debatable signal. The money position card is pure Run/BAU — it gets one Run tag in the header and no per-row dots, because dotting every row stated the obvious. The follow-up queue is entirely Run, so it carries no lane marks at all. The lesson: lane color earns its place only where the lane is a genuine triage axis (objectives, tasks). Mandatory laning becomes the noise the One-Blue Rule was trying to prevent.

Decision asked of Arief
  1. Does lane color help your scan, or add noise? Look at the Work legend line and the objective bars in Orient. Did you absorb the Run/Optimize/Transform mix faster than in variant A, or did the extra hues fight the status colors for your eye?
  2. Accept the categorical≠interactive distinction? If yes, the One-Blue Rule is clarified to "the only saturated interactive color," and the Tinted-Status Rule is formally extended to cover lanes. If no, lanes become plain text tags and we lose the at-a-glance mix.
  3. Keep the Transform→red fix? The redefinition to hsl(8 78% 50%) resolves the brand-orange collision. Worth keeping in base.css before any other screen adopts lanes.
