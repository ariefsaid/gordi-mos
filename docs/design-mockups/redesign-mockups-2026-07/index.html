The diagnosis

Five root problems survive across the repo's own audits (design-teardown-2026-07-07, design-audit-post-retrofit-2026-07-08). The recent "retrofit" patched tokens and layout; it did not cure the disease. The disease is structural.

1 · "Several apps", not one

Table workspace, accordion cascade, essay form, CRUD list, kitchen console, and blank placeholder each behave like a different product sharing a paint job. The teardown's own words. Root cause: no spine.

2 · Home makes a promise it can't keep

Cockpit KPIs sit on top of a task list. Finance tiles show — with no basis, as-of, or source. The landing is neither calm nor decisive — it's undecided. Home vs Dashboard must collapse into one.

3 · Nav teaches the database

The rail mixes destinations with implementation nouns. "Plan" means two things. "Cascade" is an interaction, not a place. Entering Kitchen feels like leaving MOS. Nav should follow jobs.

4 · Trust gaps everywhere data shows

0 / — / empty with no provenance. A leader can't tell a real zero from a broken pipeline. Kitchen stock shows green "clear" on an all-zero page. Every number needs a source.

5 · Empty states are emptied, not designed

Inbox is bare text, Ops is boxed, Review is text+refresh, Dashboard is a paragraph. Four rhythms, zero system. Plus phone controls sized for a cursor, not a thumb. Systemic patterns are missing from DESIGN.md.

What's NOT the problem

The "Quiet Control Surface" identity — one blue, white-on-near-white, restrained, data-first — is the strongest, most coherent layer of the current design. The slop lives in the IA and page grammar built on top of it. These mockups keep the identity (with 2 visual probes to test it) and rebuild the structure.

The unifying move: pick the atom

A "company OS" — cockpit + work-management + ops-capture — has no off-the-shelf convention. That gap is the design problem. Picking one spine and letting the other jobs hang off it is what dissolves the "several apps" feeling. You chose a work-management spine (Linear/Asana/Height): the work item is the atom; cockpit, capture, and money are lenses on the work graph.

Kitchen's 5 screens → folded

log = the global capture action. plan = a work item. stock = a read view. review = an approval queue (a triage). No more kitchen nav sprawl — it dissolves structurally.

Cascade → drill, not nav

Open an Objective to drill down. Open a Task to see upward context. "Cascade" is behaviour inside Work, never a top-level item.

Plan → linked where used

Reference data (COGS, recipes, price lists) is consumed where the workflow lives. A separate Reference area exists only if lookup itself becomes a frequent job.

Home ≡ Dashboard

One orient surface. A dashboard is a component embedded where decisions happen — never a sibling destination to Home.

What the consolidated prototype delivers

The α/β/γ explorations converged: α's flat IA rail + γ's Notion-like editable pages + β's multi-view databases + the deputy panel + the Standards quality-loop. One direction, five files, the locked decisions from ADR-0025.

IA: Destinations + BU-grouped Modules

Rail = Home · Work · Money · Inbox (destinations) + Kitchen/Bar/Ecommerce under Retail Ops + Roastery under B2B Ops (modules). The floor's station is one click away. (ADR-0025 D1)

Notion-like editable pages

Every detail surface (Objective/Project/Process/Task/Standard) is a contenteditable page — / block menu, drag-reorder, inline-prop popovers. (γ + D2)

Multi-view databases (β)

Tasks + Projects get Table / Kanban / Timeline view-switch. A View = saved {filters, sorts, layout, fields}. (D3d)

Deputy panel — agent-native from the front

A real mocked panel: grounded conversation, compose-to-workspace, inline @ reach, can navigate you. PMO is the floor; this exceeds it. (D4 + D5)

Standards quality-loop

A Standard (spec: target + range + cadence) lives on its Process. Steps generate checks → pass/fail → exceptions → correction tasks → audit trail. The F&B loop, end to end.

Shifts + impersonation

Retail-overall roster drives check assignment. Switch between 5 personas — nav, permissions, and Home recompose per role.

Twenty IxD grammar

One inline-cell edit primitive (Enter/Tab/click-outside commits). ⌘K popup for nav/search; docked panel for deputy + inspect. Create = new record + inline title edit. (D3a–f)

R/A ownership (corrected vocabulary)

Task = Responsible (R) + Accountable (A, UI: "Supervisor"). Project/Process = full RACI. Standard canonical (SOP = synonym). Home (not Orient). Per CONTEXT.md.

How to read these mockups

  • Every variant uses real Gordi data — real BUs (Retail Ops, B2B Ops, B2B Sales), real activities (kitchen, roastery), real money (Rp, AR/AP). No Lorem.
  • Each shows desktop shell + landing + Work view, plus mobile frames for the three role compositions (owner / lead / floor) — because Orient renders differently per persona.
  • The blue capture button floating on every screen is a deliberate probe of DESIGN.md's No-FAB Rule. The floor job ("capture a roast in <60s") needs it; decide if the rule holds.
  • Every cockpit number drills — hover/look for the drill target. A dead-end number is a defect (JTBD anchor A4).
  • Mobile tap targets are 44px throughout (the systemic P1 debt the audit flagged is paid here).
