Full redesign premise

Stop preserving the current app. Design the operating system around jobs, not around accumulated pages.

These mockups treat the current app, DESIGN.md, route map, and earlier IA as suspect. Useful decisions are reused only when they support the job. Everything else is cut, merged, renamed, or demoted.

Current design critique

  • DashboardNot a destination. It is a monitoring pattern inside the landing cockpit.
  • PlanToo abstract. Users do not wake up wanting "Plan." They need money, costs, pricing, stock, or reference records.
  • CascadeImplementation noun. Users need Objectives that drill down and Tasks that roll up.
  • ReferenceUsually not top-level. Reference data belongs inside the workflow that consumes it unless lookup is a frequent job.
  • SOP libraryToo passive. Standards need to generate checks, evidence, findings, and corrective work.
  • Kitchen navToo much module anatomy in primary nav. Activity modules need local navigation.

Three IA alternatives

Each option changes the mental model, not just the colors. Compare where the user lands, what the app calls its destinations, and what gets demoted.

Option A: Now-Centered OS

Recommended default for a first rollout.

  • Top-level: Now, Work, Ops, Money, Inbox.
  • Home + Dashboard become one cockpit named Now.
  • Money owns revenue, margin, AR/AP, COGS, pricing, and cost records.
  • Ops owns Standards, Checks, Findings, and Evidence as a control layer.
  • Objectives live inside Work, not Cascade.
Open option A

Option B: Work-Led OS

Best if management cadence is the product center.

  • Top-level: Work, Money, Ops, Inbox.
  • The default screen is Work Today, not a dashboard.
  • Objective detail is the cascade down; task detail is the cascade up.
  • Money and Ops feed exceptions into Work.
  • SOP checks and findings appear as management work.
Open option B

Option C: Ops-First OS

Best if shop-floor adoption is the gating risk.

  • Top-level: Today, Floor, Work, Money, Inbox.
  • Contributors get fast capture before management dashboards.
  • Activity modules are grouped by floor jobs, not database tables.
  • Standards and checks are visible beside capture and review.
  • Manager views are generated from captured operations.
Open option C

Redesign rules used

These replace the append-only design-doc posture.

Navigation follows jobs

Top-level destinations are user goals: orient, work, operate, handle money, triage. They are not schemas, modules, or page archetypes.

Dashboard is a component

Monitoring is embedded where decisions happen. A KPI without a drill target is removed or shown as unavailable with a reason.

Objective replaces Cascade

Users open an Objective to drill down or open a Task to see upward context. "Cascade" is behavior, not IA.

Reference stays contextual

Costs, recipes, stock, and certified numbers appear where they are used. A separate Reference area exists only if lookup becomes a frequent job.

Standards are active controls

SOPs become versioned standards, recurring checks, required evidence, findings, and corrective tasks. Long documents are attachments, not the product center.
